SECTION 1

Purpose and Scope

The Independent Valuation Model (IVM) is a browser-based auditor tool designed to independently corroborate management's fair value estimates for financial instruments under ASC 820, Fair Value Measurement. It is not a pricing system, a trading tool, or an investment advisory tool.

The IVM is intended to be used by qualified audit professionals with sufficient knowledge of derivatives and fair value measurement to exercise appropriate judgment when entering inputs and interpreting outputs. The tool produces a point estimate of fair value and a sensitivity range, both of which the auditor should compare to management's reported value to assess reasonableness.

Instruments in Scope

InstrumentPrimary MethodologyTypical ASC 820 Level
Interest Rate SwapDiscounted Cash Flow (DCF)2
Forward ContractCost-of-Carry / DCF2
Futures ContractExchange Mark-to-Market1
Convertible NoteDCF (debt) + Black-Scholes (option)3
Options & WarrantsBlack-Scholes + Monte Carlo2 or 3

What the IVM Is Not

Important Limitation The IVM does not value American-style early exercise features, barrier options, path-dependent payoffs, credit default swaps, inflation-linked instruments, or instruments with embedded call/put features beyond the conversion option in a convertible note. Do not use this model for instruments outside the scope table above without supplemental analysis and documented justification.
SECTION 2

Model Overview and Architecture

The IVM is a single self-contained HTML file. All computation is performed client-side in JavaScript, with no data transmitted to external servers (except font loading from Google Fonts, which carries no instrument data). This design ensures that sensitive client information entered into the model does not leave the auditor's machine.

Reproducibility

All deterministic calculations (DCF, Black-Scholes, cost-of-carry) produce identical results for identical inputs on every run on every device. The Monte Carlo simulation uses a fixed pseudo-random seed (Mulberry32 algorithm, seed = 20240101) so that simulation results are also fully reproducible. If the seed is changed, the model version must be incremented and this document updated.

Version Control Policy Any change to a formula, hardcoded constant, or the Monte Carlo seed constitutes a new model version. The version identifier (e.g. IVM-v1.1) is embedded in every generated working paper memo. Audit files must record which version was used for each engagement so that results can be independently reproduced.

Seeded PRNG: Mulberry32

The Mulberry32 algorithm is a 32-bit pseudo-random number generator with a single 32-bit integer seed. It passes standard statistical randomness tests (TestU01 SmallCrush) and produces uniformly distributed values in [0, 1). The implementation used in IVM-v1.1 is as follows:

Mulberry32 Implementation
seed = seed + 0x6D2B79F5
t = (seed XOR seed >>> 15) * (1 OR seed)
t = t XOR (t XOR t >>> 7) * (61 OR t)
output = (t XOR t >>> 14) / 2^32
Source: Tommy Ettinger, "Mulberry32," 2017. Verified against reference implementation.
SECTION 3

Interest Rate Swap — DCF Methodology

An interest rate swap is valued as the difference between the present value of the floating leg and the present value of the fixed leg. Each leg is modelled as a series of cash flows discounted at the applicable rate.

Formula

Fixed Leg PV
PV_fixed = Σ [r_fixed × (1/freq) × N × e^(−r_disc × t_i)] + N × e^(−r_disc × T)

Floating Leg PV
PV_float = Σ [r_float × (1/freq) × N × e^(−r_disc × t_i)] + N × e^(−r_disc × T)

Net Fair Value (Pay-Fixed Position)
FV = PV_float − PV_fixed − CVA

Inputs

InputSymbolDescriptionObservability
NotionalNFace amount — not exchangedContractual
Fixed Rater_fixedContractual coupon rateLevel 2 — Contractual
Floating Rater_floatCurrent SOFR or benchmark rateLevel 2 — Market observable
Discount Rater_discOIS rate for applicable termLevel 2 — Market observable
CVACVACredit valuation adjustmentLevel 2–3 — Counterparty credit
TermTRemaining years to maturityContractual
FrequencyfreqPayment periods per yearContractual

Hardcoded Assumptions

The model assumes a flat discount curve (single rate applied to all periods). In practice, a swap should be discounted using the full OIS curve. For audit purposes, using the mid-market OIS rate for the swap's remaining term is a reasonable approximation, and any deviation from a full curve discount should be assessed for materiality.

The model assumes continuous compounding (e^(−rt)) rather than discrete compounding. This is standard market convention for OIS-discounted swaps and is consistent with Bloomberg and Reuters swap pricing conventions.

Authoritative source: Hull, J.C., Options, Futures and Other Derivatives, 11th ed., Chapter 7 (Swaps). ASC 815-20, ASC 820-10-35.
SECTION 4

Forward Contract — Cost of Carry

A forward contract's fair value is the present value of the difference between the current forward price and the contracted delivery price. The forward price is derived from the spot price using the cost-of-carry model.

Current Forward Price
F₀ = S × e^((r − q) × T)

Fair Value (Long Position)
FV = (F₀ − K) × e^(−r × T) × Size

Fair Value (Short Position)
FV = (K − F₀) × e^(−r × T) × Size
InputSymbolDescriptionObservability
Spot PriceSCurrent market price of underlyingLevel 1 or 2
Delivery PriceKContractual settlement priceContractual
Risk-Free RaterContinuous risk-free rateLevel 2 — Treasury curve
Yield / Conv. YieldqDividend yield (equity) or convenience yield (commodity)Level 2 or estimated
Time to MaturityTRemaining yearsContractual
Contract SizeSizeUnits per contractContractual
Authoritative source: Hull, Chapter 5 (Determination of Forward and Futures Prices). ASC 820-10-35.
SECTION 5

Futures Contract — Mark to Market

Exchange-traded futures are marked to market daily using the exchange's official settlement price. The fair value of a futures position is simply the change in settlement price since entry, multiplied by the contract multiplier and quantity.

Unrealised P&L / Fair Value (Long)
FV = (Settlement Price − Entry Price) × Multiplier × Quantity

Fair Value (Short)
FV = (Entry Price − Settlement Price) × Multiplier × Quantity
ASC 820 Level 1 Futures traded on regulated exchanges (CME, ICE, NYMEX, CBOE) with daily published settlement prices are classified as Level 1 under ASC 820-10-35-40. The settlement price is used without adjustment. No model is required; this calculation is purely arithmetic. The auditor must obtain the official settlement price report from the exchange as of the valuation date.
Authoritative source: CME Group Daily Settlement Procedures; ASC 820-10-35-37 through 35-41.
SECTION 6

Convertible Note — Bifurcated Model

A convertible note is bifurcated into two components per ASC 470-20: a straight debt component (valued using DCF) and an embedded conversion option (valued using Black-Scholes). The total fair value is the sum of the two components.

Component 1: Straight Debt (DCF)

Present Value of Straight Debt
PV_debt = Σ [(coupon/2 × Face) × e^(−r_disc × t_i)] + Face × e^(−r_disc × T)

The model uses semi-annual coupon periods. The discount rate r_disc is the credit-adjusted market rate for non-convertible debt of equivalent seniority and term — the most significant Level 3 input in this model.

Component 2: Embedded Conversion Option (Black-Scholes)

Shares per Note
n = Face Value / Conversion Price

Option Value
Option_FV = BlackScholes(S, K=ConversionPrice, T, r_rfr, σ, q=0, "call") × n

Total Fair Value

FV_total = PV_debt + Option_FV
Level 3 Inputs — Heightened Scrutiny Required Two inputs are typically unobservable and require documented support in the audit file: (1) the credit-adjusted discount rate, which should be supported by comparable debt issuances, credit spread analysis, or a credit rating assessment; and (2) equity volatility, which for private companies must be derived from a comparable public company analysis. These inputs must be disclosed in the financial statements per ASC 820-10-50-2(bbb).
Authoritative source: ASC 470-20 (Debt with Conversion and Other Options); Hull, Chapters 15 and 30; ASC 820-10-35-52.
SECTION 7

Options & Warrants — Black-Scholes & Monte Carlo

Black-Scholes Analytical Model (Primary)

The Black-Scholes model provides a closed-form solution for the fair value of European-style options on assets with continuous dividend yields. It is the primary valuation output of the IVM for options and warrants.

Call Option
C = S·e^(−qT)·N(d₁) − K·e^(−rT)·N(d₂)

Put Option
P = K·e^(−rT)·N(−d₂) − S·e^(−qT)·N(−d₁)

d₁ and d₂
d₁ = [ln(S/K) + (r − q + σ²/2)·T] / (σ·√T)
d₂ = d₁ − σ·√T

Greeks Computed

GreekFormulaInterpretation
Delta (Δ)e^(−qT)·N(d₁) [call]; −e^(−qT)·N(−d₁) [put]$ change in option per $1 move in S
Vega (ν)S·e^(−qT)·√T·φ(d₁)$ change per 1% change in volatility

Monte Carlo Simulation (Corroborating)

The Monte Carlo engine simulates 1,000 terminal stock price paths under geometric Brownian motion and prices the option as the discounted average payoff. It serves as a cross-check on the Black-Scholes result, not as the primary output.

Terminal Price (each path)
S_T = S × exp[(r − q − σ²/2)·T + σ·√T·Z], where Z ~ N(0,1)

Monte Carlo Value
MC = e^(−rT) × (1/n) × Σ max(S_Ti − K, 0)  [call]
Primary vs. Corroborating Black-Scholes is the primary output. The Monte Carlo result is included as a cross-check. With n=1,000 paths and a fixed seed, the MC result should be within approximately 2% of the Black-Scholes value for standard European options — a material divergence (>5%) should be investigated before relying on either number.
Authoritative source: Hull, Chapters 15 (Black-Scholes) and 21 (Monte Carlo Simulation); ASC 820-10-35-24A.
SECTION 8

ASC 820 Hierarchy Classification Logic

The IVM automatically classifies each instrument based on the typical nature of its significant inputs. The classification is a default based on instrument type and must be overridden by the auditor where the facts of the specific instrument differ from the default.

InstrumentDefault LevelBasisOverride Conditions
Futures Contract1 Exchange-quoted settlement price (ASC 820-10-35-40) If contract is not exchange-traded, classify as Level 2 or 3
Interest Rate Swap2 Observable swap curves, SOFR fixings, OIS rates (ASC 820-10-35-47) Elevate to Level 3 if CVA is significant and uses unobservable credit spreads
Forward Contract2 Observable spot prices and risk-free rates (ASC 820-10-35-47) Elevate to Level 3 if underlying is illiquid or convenience yield is estimated
Exchange-Traded Option2 Observable implied volatility from active option markets Level 1 if quoted price for identical option is available
OTC Option / Warrant3 Volatility is unobservable for OTC and private instruments (ASC 820-10-35-52) Reduce to Level 2 if implied vol from active market for similar instrument exists
Convertible Note3 Credit-adjusted discount rate and equity volatility are both unobservable Rarely reclassifiable to Level 2 — requires all significant inputs to be observable
Auditor Override Responsibility The automatic classification is a starting point only. The auditor must assess whether the specific facts of the instrument under review — including its liquidity, the availability of quoted prices, and the observability of each significant input — support the default classification. Document any override and the basis for it in the working papers.
SECTION 9

Monte Carlo Simulation Engine

Normal Random Variate Generation: Box-Muller Transform

The IVM generates standard normal random variates using the Box-Muller transform applied to pairs of uniform random numbers from the Mulberry32 PRNG:

U₁, U₂ ~ Uniform(0,1)  [from seeded PRNG]
Z = √(−2·ln U₁) · cos(2π·U₂)  ~ N(0,1)

To avoid a degenerate case where U₁ = 0 (causing ln(0) = −∞), the implementation clamps U₁ to a minimum of 1×10⁻¹⁰.

Path Generation

Each path simulates the terminal stock price at expiry under risk-neutral measure (Geometric Brownian Motion):

S_T = S · exp[(r − q − σ²/2)·T + σ·√T·Z]

The term (r − q − σ²/2) is the risk-neutral drift corrected for the Itô correction (σ²/2). This is the standard discretisation for a single time step and is exact (not an approximation) for the terminal distribution of GBM.

Confidence of Results

With n=1,000 paths, the standard error of the Monte Carlo estimate is approximately σ_MC / √1000 where σ_MC is the standard deviation of discounted payoffs. The IVM displays this standard error alongside the Monte Carlo result. Auditors should note that for deep out-of-the-money options, standard error may be large relative to the estimated value; in such cases, Black-Scholes is the more reliable primary output.

SECTION 10

Normal CDF Implementation

The standard normal cumulative distribution function N(x) is computed using the rational polynomial approximation from Abramowitz & Stegun (1964), formula 26.2.17:

Abramowitz & Stegun Polynomial (max error: 7.5×10⁻⁸)
For x ≥ 0:
t = 1 / (1 + p·|x|/√2) where p = 0.3275911
y = 1 − (a₁t + a₂t² + a₃t³ + a₄t⁴ + a₅t⁵)·e^(−x²/2)
N(x) = (1 + sign(x)·y) / 2

Coefficients:
a₁ = 0.254829592   a₂ = −0.284496736   a₃ = 1.421413741
a₄ = −1.453152027   a₅ = 1.061405429

Hardcoded Assumptions & Constants

The following assumptions are built into the model and cannot be changed by the user. Any deviation from these assumptions in the instrument being valued must be assessed for its impact on the fair value conclusion.

Exercise style European only Black-Scholes assumption High — American options may be worth more due to early exercise; supplement with binomial model
Dividend treatment Continuous dividend yield Merton (1973) extension to Black-Scholes Low for most instruments; may be material for high-dividend stocks with discrete dividends

Forward Contract✓Single-leg forward only. No forward rate agreements (FRAs) or multi-leg structures.

SECTION 13

Input Documentation Requirements

Every significant input to the IVM must be documented in the Input Sourcing Log generated by the tool. The following minimum standards apply to each input category.

Level 1 Inputs

Document the exchange, the specific price source (e.g. "CME Group daily settlement file, 31 Dec 2024"), and the date of the quote. Attach or cross-reference the source document in the audit file.

Level 2 Inputs

Document the data provider (Bloomberg, Refinitiv, ICE, Federal Reserve H.15), the specific screen or dataset (e.g. "Bloomberg SOFR screen, SOFRRATE Index"), and the date. For rates, document whether the rate is a spot rate, forward rate, or yield-to-maturity, and confirm it matches the convention used in the model (continuous compounding).

Level 3 Inputs — Heightened Requirements

Level 3 Inputs Require Additional Audit File Documentation For each Level 3 input, the audit file must contain: (1) a description of the methodology used to develop the input; (2) the data sources considered; (3) the range of reasonable estimates; and (4) the basis for selecting the point estimate used. This documentation is required by ASC 820-10-50-2(bbb) for disclosure purposes and should inform the auditor's assessment of whether management's inputs fall within a reasonable range.

Volatility (Options, Warrants, Convertible Notes)

For exchange-traded options: document the implied volatility sourced from the option chain as of the valuation date, including moneyness and expiry of the reference option. For OTC options and warrants on private companies: document the comparable public company analysis, including the companies selected, their historical volatility over the relevant measurement period (typically 1-year), and the basis for any adjustments.

Credit-Adjusted Discount Rate (Convertible Notes)

Document the basis for the rate selected, which may include: yields on comparable publicly traded debt of the issuer, credit rating analysis, credit spread benchmarking against rated peers, or a market participant survey. The selected rate should be stress-tested in the sensitivity analysis.

Model Validation & Testing

The IVM is accompanied by a separate Model Validation Harness (model-validation.html) which contains 24 test cases across three tiers. The harness must be run before relying on the IVM for any engagement, and the results must be printed and retained in the audit file.

TierDescriptionToleranceFailure Implication
Tier 1 — Boundary Conditions Mathematically provable cases (e.g. at-par swap = $0, put-call parity) ≤ $0.01 Code error — do not use model until resolved
Tier 2 — Published Benchmarks Textbook examples with known answers (Hull Example 15.6, CFA cases) ≤ $0.05/unit Systematic formula error — investigate before use
Tier 3 — Consistency Tests MC convergence, monotonicity, delta bounds, CDF accuracy Varies Engine integrity issue — investigate and document

Independent Fixed Reference Test

The following result is computed independently in Microsoft Excel and serves as a fixed external reference that breaks the self-referential loop of the in-tool test suite. Any version of the IVM must reproduce this result within $0.05.

Hull Example 15.6 — Fixed External Reference (Excel)
Inputs: S = $42, K = $40, T = 0.5yr, r = 10%, σ = 20%, q = 0%, European Call
d₁ = [ln(42/40) + (0.10 + 0.02)×0.5] / (0.20×√0.5) = 0.7693
d₂ = 0.7693 − 0.20×√0.5 = 0.6279
N(d₁) = 0.7791   N(d₂) = 0.7349
C = 42×0.7791 − 40×e^(−0.05)×0.7349 = 32.72 − 27.96 = $4.76
